# Hybrid JWKS + key-value JWT verification, under the existing `com.microservice.authentication.*` property namespace

Context: `scala-address-service` needed JWT signature verification. The obvious-looking path was to standardize on JWKS-only, since `authentication-service`'s `/.well-known/jwks.json` endpoint already serves both RSA (prod) and HMAC-as-JWK (non-prod) keys, and every other Spring service in this system resolves verification via a JWKS URI. But `authentication-common`'s `AuthenticationProperties` already defines a hybrid contract — `jwt.keyValue` (secret or PEM public key) as well as `jwk.keySetUri` — and it's actively used, not vestigial: `authentication-service.yml` and `applicationDev.yml` set a real `com.microservice.authentication.jwt.keyValue`, and `person-service`'s test config sets the same property to avoid a live network dependency in unit tests.

Decision: `scala-address-service` keeps both verification paths (JWKS preferred, key-value as a fallback), reading them under the same `com.microservice.authentication.jwk.key-set-uri` / `com.microservice.authentication.jwt.key-value` property names the rest of the system already uses, rather than inventing service-local `JWKS_URL`/`JWT_SECRET` env vars.
